linuxqq无法调用fcitx5中文输入法

linuxqq是Electron应用，而Electron应用在Wayland下常有无法使用中文输入法的问题（表现为fcitx5无法在该应用的窗口下正常运行），这也算是archlinux的老疑难杂症了。其间我逛了各种神秘论坛/大佬博客，找到的解决方法大体如下：

  1. 在Linuxqq的启动命令中注入环境变量参数

    我使用fuzzel作为程序启动器，它会自动寻找每个程序的.desktop文件（通常在/usr/share/applications或~/.local/share/applications下，且后者中的配置会覆盖前者）并用其中的Exec参数的值作为启动命令，此时需要在linuxqq.desktop中更改为这条：

    Exec=env QT_IM_MODULE=fcitx GTK_IM_MODULE=fcitx XMODIFIERS=@im=fcitx /usr/bin/linuxqq

    再次启动qq有概率修好（玄学，WeChat用这个方法就怎么也修不好，笔者已放弃WeChat）

  2. 在fcitx的启动命令中指定参数的值

    不知道从哪个犄角旮旯翻出来的教程，笔者照1的操作设定后，linuxqq已经可以正常使用中文输入法，但是候选框会频繁闪烁和掉字。最后在fcitx5-wayland-launcher.desktop中将启动命令修改如下：

    Exec=/usr/lib/fcitx5-wayland-launcher --reopen --wayland-text-input-version=3

    就这样fcitx5窗口稳定下来了，原理未知，感兴趣的小伙伴可以去fcitx wiki找找原因，我是啃不动生肉了只能放弃了。

  3. 使用flatpak安装qq

    如题，这才是arch qq的最终解法，也是我折腾了半天后的方案。

    flatpak install flathub com.qq.QQ

    舒服呀。。。

重置BIOS后启动项消失

笔者的ThinkPad出了一些问题，听从了ai的话重置了BIOS，结果连系统都进不了了，我已急哭，，，

千万别盲目相信ai！！！！！！

  1. 解决方法

    经过排查发现，重置BIOS会擦除固件中NVRAM储存的grub启动项文件位置，导致无法找到linux的启动项。只需要从u盘启动（其他盘也是可以的，装有系统镜像就行）进入tty重新挂载一次分区（根据你当时挂载的目录关系来，不然执行下面的命令系统也找不到启动项文件），然后执行一次命令：

    grub-install --target=x86_64-efi --efi-directory=/your/efi/path --bootloader-id=自己取一个启动项的名字

    注：命令需根据不同的平台架构调整，上述命令适用于UEFI模式。

  2. 原理

    grub-install命令会重写引导器，在NVRAM中注册一条启动项，把grub.efi的位置传入，让机器能重新读取启动项。
